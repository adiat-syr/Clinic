# Разрывы перед этапом 7 — план ограниченного дополнения

Исходная база: этап 6, `e0424ec`. В рабочем дереве уже находятся последующие исправления CLI выдачи/восстановления credentials и смены email; их сохраняем. Реальные данные, production и внешние интеграции не разрешены.

| Область              | Реальное состояние                                                    | Решение в текущем объёме                                                                                                                                                                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ручная запись        | В roadmap отложена, POST admin/appointments отсутствует               | Пользователь явно разрешил пересмотреть границу. Согласовать подтверждаемую процедуру; нельзя вызывать public API с галочкой сотрудника                                                                                                                                                                                                 |
| Согласие по телефону | Только WEB_CHECKBOX, нет доказательства отдельного действия пациента  | Предложен самостоятельный цифровой шаг пациента + короткоживущий одноразовый код для сотрудника. Без подтверждения не создавать запись. Пользователь выбрал этот процесс: срок 5 минут, одна запись на код, конкретная версия согласия, исходный online flow сохраняется основным; юридическая применимость до production не заявляется |
| RU/KK staff UI       | RU; поля каталога двуязычные                                          | Полный словарь интерфейса, переключатель с сохранением языка в навигации, KK тексты каталога, даты/статусы/ошибки/диалоги; Stitch сохраняется                                                                                                                                                                                           |
| Вход/доступ          | Cookie/MFA/RBAC/CSRF, idle polling fix, offline CLI                   | Проверить обе роли, неверный/повторный MFA, logout, смену пароля, блокировку/отзыв; сохранить backend-контроль                                                                                                                                                                                                                          |
| Бронирование         | Общий service, idempotency, doctor locks, exclusions                  | Все новые создания только через существующее ядро; проверить онлайн/ручную конкуренцию, rollback, одноразовость и retry                                                                                                                                                                                                                 |
| Production           | Не выполнены юридические, эксплуатационные и конфигурационные условия | Составить отдельный список блокеров, не объявлять готовность и не выполнять деплой                                                                                                                                                                                                                                                      |

Приёмка дополнения: нет создания без самостоятельного согласия/действующего основания; нет plaintext контактов/токенов в URL/логах/localStorage; новые HTTP DTO strict и no-store; авторизация/мутация в одной транзакции; RU/KK маршруты и роль проверены браузером; ограничения PostgreSQL проверены на собственной временной БД. Если выбран вариант блокировки ручной записи, endpoint создания не открывается и причина фиксируется явно.

Правовая отправная точка: [официальный текст закона РК о персональных данных](https://old.adilet.zan.kz/rus/docs/Z1300000094), статьи 7–8. Требуется подтверждаемое получение согласия; конкретный цифровой процесс, идентификация, состав текста, сроки, оператор и криптосредства должны отдельно приниматься юристом/клиникой. Текущий синтетический текст seed для реальной работы непригоден. Галочка сотрудника не доказывает действие пациента.
