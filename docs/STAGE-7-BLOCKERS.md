# Блокирующие условия коммерческого запуска

Это перечень незакрытых задач, а не подтверждение готовности. Этап 7 и production не выполнялись. Разрешены только локальные синтетические данные. Успешные автоматические тесты не закрывают перечисленные условия.

| Область                          | Что требуется до реальных данных                                                                                                                                                                            | Проверяемый результат                                                                                                                                                                                                 |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Юридическая проверка             | Юрист/клиника проверяют применимую редакцию законодательства РК, состав и доказуемость согласия, идентификацию, языки, оператора/цели, контакты/лицензию/рекламу, сроки и отзыв, применимость криптосредств | Подписанные решения и утверждённые RU/KK документы, вместо synthetic seed; определены ответственные                                                                                                                   |
| Дополнительная телефонная запись | Проверить самостоятельное цифровое действие пациента, доказательства, срок/объём согласия, возможность обработать обращение без такого способа; утвердить правила сотрудника                                | Письменное разрешение на конкретный процесс. Код не является доказательством личности; флажок сотрудника/устное «согласен» не заменяет согласие                                                                       |
| География и поставщики           | API, PG, ключи, журналы, backups и связанные runtime-хранилища планируются в Казахстане; проверить договоры и передачи данных                                                                               | Подтверждение размещения и условий поставщиков; внешние SMS/CDN/мониторинг не включаются автоматически                                                                                                                |
| Секреты и конфигурация           | Отдельные реальные ключи/DB credentials, secret storage, права, ротация и восстановление ключей, NTP, управление Origin/домена/зоны/режима данных                                                           | Проверенная конфигурация без .env секретов в артефактах/логах/клиенте; смена CONTACT/AUTH ключа не уничтожает доступ к существующим данным                                                                            |
| Права PostgreSQL                 | Отдельные migration/operator/runtime роли, запрет superuser/owner/DDL/TRUNCATE и ненужного DELETE; минимальные GRANT, запрет прямого доступа извне                                                          | Положительные и отрицательные тесты под настоящей runtime ролью. Текущие integration tests используют тестового владельца и это не проверяют                                                                          |
| Новая таблица согласий           | Runtime нужны SELECT/INSERT и ограниченная операция потребления patient_consent_receipts; оператор cleanup получает только необходимые права. Immutable trigger и FK не заменяют GRANT                      | Нельзя подменить текст/версию/контакты/срок или повторно использовать код; runtime не может снять ограничения. Регламент удаления отдельно учитывает эту таблицу                                                      |
| HTTPS/proxy/cookies              | TLS, доверенный proxy и корректный trust proxy, точный Origin, Secure/HttpOnly/__Host-/SameSite, CSP/headers, no-store для приватных ответов, исключение тела/headers из proxy/access logs                  | Ручные браузерные тесты через реальный HTTPS proxy; HTTP dev-cookie и тестирование loopback этого не доказывают                                                                                                       |
| Доступ сотрудников               | Контролируемая выдача/восстановление после проверки личности, TTY/Authenticator приёмка, разделение операторских полномочий, отзыв при уходе                                                                | Документированная процедура; CLI с доступом к серверу/ключам не должен быть доступен обычному пользователю машины                                                                                                     |
| Backup и восстановление          | Шифрованные резервные копии и ключи отдельно, география KZ, расписание, доступ, RPO/RTO, тест восстановления в отдельной среде                                                                              | Восстановлены БД, ключи и документы, проверена читаемость контактов и отсутствие двойной записи; сроки/удаления повторно применены к восстановленной копии                                                            |
| Хранение и удаление              | Утвердить цели/сроки по таблицам, обработку отзыва и запросов, logs/backups/legal holds; создать cleanup jobs                                                                                               | Доказуемое удаление/обезличивание. Soft delete/отметка withdrawnAt/истечение кода не равны удалению. Неиспользованные receipts содержат зашифрованные контакты и требуют очистки; использованные связаны FK с приёмом |
| Эксплуатация и безопасность      | Ограничения ресурсов/пула/таймаутов, proxy/shared rate limits, нагрузка/DoS, dependency/secrets review, мониторинг без PII и runbook инцидентов                                                             | Прогоны под целевым профилем, проверенные alerts, ответственные и регламент; полный security audit в текущем объёме не выполнялся                                                                                     |
| Продуктовая приёмка              | Реальный каталог/цены/расписание/контент/контакты/лицензия, профессиональная проверка RU/KK, доступность, Safari/Firefox и физические устройства                                                            | Приёмка клиникой. Наличие полного словаря не означает профессиональной медицинской/юридической вычитки                                                                                                                |
| Публикация и SEO                 | Реальный домен, canonical/hreflang, управляемый rebuild каталога, hosting 404/fallback, noindex до открытия                                                                                                 | Проверенный staging с synthetic данными и затем отдельно разрешённый релиз; локальная сборка не является deployment                                                                                                   |

Для технической процедуры согласия использован как отправная точка [официальный текст закона РК «О персональных данных и их защите», статьи 7–8](https://old.adilet.zan.kz/rus/docs/Z1300000094). Требование подтверждаемого получения согласия не позволяет считать любую реализацию checkbox или одноразового кода автоматически законной. Детальная правовая квалификация, полный состав обязательных реквизитов и применимость к частной клинике в текущем окружении не подтверждены.
