# Результат этапа 5

Дата: 05.11.2026. Выполнен клиентский React-сайт; этап 6 не начат, deployment не выполнялся. Только синтетические данные. База — commit 2853799 этапа 4; backend API и транзакционное ядро не переписывались.

## Страницы и сценарии

- RU/KK: главная, услуги и цены, карточка услуги, специалисты, карточка специалиста, онлайн-запись, контакты/порядок обращения и privacy, экран 404.
- Реальные public services/doctors API с обработкой пагинации, типизацией и Zod/mini валидацией; общий TanStack Query слой. Поиск по каталогу и специалистам, переходы к записи с service/doctor ID. Цены/длительности/назначения не копируются из Stitch.
- Выбор услуги/назначенного врача, даты и свободного времени API. Зона времени подписана; устаревшие календарные даты макета не используются. Никаких фиктивных доступных интервалов.
- Имя/телефон, актуальное согласие API и непредустановленный checkbox. Клиентская валидация совпадает с основными backend-правилами; сервер остаётся окончательным валидатором. Не добавлены диагноз/ИИН/заметки/файлы.
- Origin/CSRF cookie + header, настоящий POST appointments, PENDING-результат с reference, временем и условиями. Это заявка, не ложное подтверждение приёма. Ответ повторной отправки учитывает актуальный status API.
- Состояния загрузки/ошибки/retry/пустого расписания, SLOT_UNAVAILABLE, OFFER_CHANGED и CONSENT_CHANGED. Обновлённая версия согласия снимает старое подтверждение. Слот может быть занят между просмотром и POST: ошибка не превращается в успех.
- Случайный idempotency key хранится только в памяти попытки. При потере ответа или неопределённом 5xx body/key сохраняются для безопасного retry, поля временно блокируются; уход со страницы при отправке/неопределённом результате вызывает browser beforeunload. При успехе контакты и попытка очищаются. Persistent storage для контактов/токенов не используется.

## Граница просмотра, переноса и отмены

Действующий backend предоставляет эти операции **только ADMIN/RECEPTIONIST с MFA**. Public GET по reference/телефону, отмена или перенос посетителем отсутствуют. В этапе 5 не создавался обход этих прав и не добавлялся staff UI этапа 6. Посетитель видит результат текущей попытки в памяти страницы и порядок обращения в регистратуру. После перезагрузки номер не восстанавливается из localStorage.

API-перенос, отмена, конфликты version, сохранность исходной записи и освобождение времени повторно проверены существующими HTTP/PG тестами этапа 4. Самостоятельный клиентский кабинет/управление записью не заявляются реализованными: для них нужен отдельно согласованный public capability API или работа сотрудника. В synthetic среде реальный телефон регистратуры ещё не утверждён, поэтому нет декоративной кнопки звонка на чужой номер.

## Дизайн и архитектура

Изучены README/AGENTS/TASKS, отчёт этапа 4, OpenAPI и код public DTO/router, материалы Stitch (HTML, DESIGN и PNG основных публичных экранов), текущие токены и компоненты. Использованы frontend-design, ui-ux-pro-max и vercel-react-best-practices. Применены цвета/типографика/светлые rounded cards/плашки цен/шаги записи/mobile bar Stitch. Реальные имена/портреты, лицензия, реквизиты, рейтинги и claims из демонстрационных HTML не перенесены. При отсутствии разрешённых локальных портретов — инициалы. Desktop — адаптация карточек в колонки; pixel-perfect совпадение с каждым PNG не заявляется.

Сохранены React/Vite/TypeScript strict, локальные fonts и CSS tokens. Разделены API client, i18n, Booking feature и общая страница/карточки. Маршруты используют обычные same-origin ссылки и history браузера, без новой router-зависимости: текущий небольшой public-сайт допускает документную навигацию, формы при уходе не сохраняют контакты. Этап 6 сможет добавить свой router без изменения API. Backend/Prisma/migrations/RBAC/MFA не изменены.

Prerender через Vite SSR + ReactDOMServer строит 22 ru/kk страницы, включая карточки, из public PostgreSQL DTO. В HTML только публичный каталог; JSON snapshot экранирует `<`, React экранирует текст. Есть локальные SEO title/description, configurable canonical/hreflang/sitemap и 404.html. Снимок обновляется контролируемой root-командой `npm run build` после изменения каталога. Для строгой проверки `SEO_REQUIRED=true`; без БД нестрогая dev-сборка допускает shell с предупреждением. `PUBLIC_SITE_ORIGIN` должен быть утверждённым HTTPS origin, синтетический домен использовался только для локального теста. Noindex/robots запрет сохранены до production-приёмки. Выдача HTTP 404/статических маршрутов конфигурируется хостингом на этапе 7, здесь проверены UI и HTML артефакт 404.

## Осталось и ограничения

1. Public просмотр/перенос/отмена не поддержаны текущим backend; доступны сотруднику через существующий API, будущий staff UI — этап 6. Public функциональность не имитируется фиктивными кнопками.
2. Реальные реквизиты/лицензия/контакты/портреты, medical copy и профессиональная проверка KK/ru ещё требуют клиники. Synthetic labels не снимаются; правовая страница не является юридическим заключением. Реальных данных не подключать.
3. Проверен Chromium; Safari/Firefox, настоящие мобильные устройства, полноценная screen-reader/контрастная приёмка и production hosting/TLS не проверялись. Видимый фокус/семантические labels/checkbox/alert/status/mobile nav реализованы; итоговый accessibility sign-off до production остаётся открытым.
4. SSR snapshot требует доступной БД и собранного API (root build делает правильный порядок); при изменениях каталога нужен rebuild. Реальная публикация, indexability, origin и HTTP 404 routing — этап 7. Никакой remote deployment не выполнен. Удалённый CI обновлён, но не запускался в GitHub.
5. Bundle ~518.5 kB minified (~156.4 kB gzip); Vite выдаёт предупреждение >500 kB. Оно не скрыто увеличением лимита. Route splitting/дальнейшее сокращение bundle возможны после измерений; исходный каркас уже содержал React Query/React и был около 486 kB.
6. Idempotency key и контакты живут только на текущей странице: закрытие вкладки теряет попытку, beforeunload предупреждает при отправке/неопределённом ответе. Клиент не гарантирует восстановление после закрытия браузера. Сроки хранения, cleanup/keys, legal/privacy, DoS/proxy/backup и готовность реального окружения — прежние задачи этапа 7.
7. Идемпотентный seed сохраняет прошлые окна, не генерирует фиктивные новые слоты. Если local catalogue имеет старое расписание, оператор должен создать будущие окна через существующий staff API; UI честно показывает отсутствие времени.
