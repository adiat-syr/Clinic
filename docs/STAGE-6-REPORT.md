# Этап 6 — рабочее пространство клиники

Дата: 05.11.2026. Основа: коммит этапа 5 `96f433c`. Выполнен только этап 6; production, реальные данные, внешние интеграции и этап 7 не запускались. Отчёт фиксирует выполненные проверки и открытые ограничения, а не сертификацию безопасности/законодательства.

## Реализовано

- `/admin`: вход паролем и отдельным MFA, полный доступ только после второго фактора, выход, смена своего пароля. `/admin/profile` — собственный пароль, отзыв всех своих сессий после изменения.
- `/admin/appointments`: дата клиники, врач, статус, серверная пагинация по 20, поиск номера на текущей странице. Контакты не загружаются списком: отдельная карточка расшифровывается существующим backend и пишет audit. Подтверждение, отмена, завершение/неявка по допустимым переходам; перенос по реальным слотам с version и проверкой quote. Конфликт занятого времени сохраняет исходную запись.
- `/admin/schedule`: день/семь дней от даты, рабочие интервалы и приёмы, свободные слоты выбранного дня для врача/услуги. Создание, изменение и удаление интервалов через существующий API. Перерыв — разрыв интервалов; пересечения и сохранность записей проверяются backend/PG.
- `/admin/doctors`, `/admin/services`: создание/редактирование, отдельные RU/KK поля, цены KZT/длительности, активность, назначения услуг. Подтверждение деактивации с предупреждением о сохранённых будущих приёмах. Slug неизменяем после создания; загрузок фото нет.
- `/admin/staff`: неактивный сотрудник без секретов, смена роли, включение/блокировка, отзыв сессий с подтверждением; защита последнего ADMIN остаётся серверной. Пароль/MFA выдаются прежней offline CLI.
- `/admin/audit`: технические события с диапазоном дат и пагинацией. Проверенный отзыв согласия в карточке доступен только ADMIN; не является удалением/автоматической отменой.
- Loading/error/empty/retry, конфликты, modal подтверждения, закрытие приватных карточек при 401/отзыве/скрытии страницы. Адаптивные sidebar/menu, формы, карточки и таблицы по системе Stitch. Исходники дизайна сохранены.

ADMIN получает все перечисленные разделы. RECEPTIONIST получает записи, расписание и собственный пароль. Обе роли работают с общеклиническими записями согласно существующей модели; ограничения по филиалу/своему врачу отсутствуют в модели. Backend проверяет роль и актуальность сессии на каждом защищённом запросе; UI не предоставляет альтернативного обхода.

Ручное создание сотрудником не добавлено: существующий API и roadmap откладывают его до отдельной процедуры согласия. Глобального поиска по телефону/имени, экспорта контактов, публичного управления записью, CRM и медкарт нет.

## Архитектура и минимальные backend-изменения

Публичный сайт сохранён; admin загружается отдельным lazy chunk. Существующий transport получил поддержку 204 без попытки JSON parse. Модуль `admin/api.ts` содержит Zod DTO и whitelisted запросы. Перед мутацией берётся актуальный CSRF; cookie остаётся HttpOnly и не читается JS. Приватный QueryClient отделён от public, не персистируется и очищается на выходе/401/уходе/скрытии. Пароли, MFA и контакты не попадают в localStorage, URL, аналитику или новые логи. Для кадровых действий используется прежняя CLI и backend, а не новый механизм выдачи секретов.

При подключении периодической проверки выявлено: прежний `GET /auth/me` обновлял lastSeenAt, поэтому polling мог бесконечно продлевать idle сессию. `AuthService.me` теперь использует внутреннюю опцию `touch:false`; проверка MFA/роли/блокировки/сроков и транзакция сохранены. Интерактивные запросы по-прежнему продлевают активность. Новая регрессия подтверждает, что проверка на 29-й минуте не изменяет lastSeenAt и после 30 минут даёт 401.

Защищённые GET списка/карточки записей дополнены четырьмя RU/KK названиями врача/услуги из существующей связи doctorService: очередь остаётся понятной после деактивации каталога без выдачи ADMIN API регистратору. Поля additive/optional в общем OpenAPI summary; публичный ответ не изменён. Это текущие названия, не исторические snapshots. Контакты по-прежнему только в карточке с аудитом. Миграции, exclusion constraints, схема Prisma и транзакционный lock-протокол не изменялись.

## Открытые ограничения и непроверенное

1. Staff UI на русском; RU/KK тексты каталога и публичный сайт сохранены. Полный казахский перевод admin из общего плана дизайна остаётся незакрытым, вместе с языковой приёмкой клиникой. Его нельзя считать проверенным по существованию RU/KK полей.
2. Проверен Chromium на Windows, а не Safari/Firefox, физические телефоны или полноценная ручная screen reader-приёмка. Native labels, live errors и modal dialog используются, но это не сертификация доступности.
3. Интервалы расписания не имеют optimistic version в существующем контракте: операции сериализуются и защищают записи, но конкурирующие корректные правки могут последовательно заменить друг друга. Нужно перечитывать состояние; version записей сохранён. При росте каталога/нагрузки нужна отдельная приёмка пагинации/производительности.
4. Staff-календарь использует согласованную `Asia/Almaty` и текущий offset +05 для введённых дат. Смена зоны клиники/исторические правила времени потребуют расширить общие метаданные и конвертацию, а не менять часовой пояс браузера.
5. Vite предупреждает о public chunk ~524 kB (gzip ~157 kB); отдельный admin chunk ~63 kB (gzip ~13.5 kB). Не блокирует сборку; оптимизация публичного bundle не выполнялась в рамках админки.
6. Работа API на каждом запросе fail-closed, но уже показанный экран не может мгновенно узнать об отзыве без сети: проверка при запросе/возврате и каждые 60 секунд. При недоступности `/auth/me` приватный экран закрывается. Сетевой сбой logout не доказывает серверный отзыв, UI предупреждает.
7. Ручная TTY/Authenticator/HTTPS Secure-cookie приёмка, реальные proxy/GRANT/TLS, ротация ключей, backup/restore, retention и cleanup, проверка нагрузки, правовой контент/размещение в Казахстане остаются из AUTH.md/TASKS этапу 7. Штатные credentials рабочей среды не создавались; общий пароль не введён.
8. Полный security/dependency audit не выполнялся; существующие тесты безопасности пройдены. Наличие checkbox отзыва не означает исполнения юридической процедуры или удаления данных.

Инструкция сотруднику: [ADMIN-GUIDE.md](ADMIN-GUIDE.md). Локальный адрес: `http://127.0.0.1:5173/admin`, `npm run dev` и локальный PostgreSQL должны быть запущены. Работа остановлена перед этапом 7; перечисленные ограничения требуют отдельной приёмки, реальные данные не допускаются.
