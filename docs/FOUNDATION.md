# Техническая основа и рабочие допущения

Этот документ фиксирует решения этапа 1. На этапе 2 модель и миграции уже реализованы; текущие команды запуска БД, гарантии и ограничения — в [DATABASE.md](DATABASE.md), результаты — в [STAGE-2-REPORT.md](STAGE-2-REPORT.md). Упоминания схемы без моделей ниже относятся к исходному этапу 1.

Объём: только этап 1. Сайт пока не принимает заявки. Данные реальной клиники не подтверждены; артефакты Stitch являются визуальным референсом.

## Решения

- Монорепозиторий npm workspaces: `@clinic/web`, `@clinic/api`, `@clinic/contracts`. Все пакеты private; общий lockfile. ESM и TypeScript strict; web использует Bundler resolution, backend/contracts — NodeNext.
- Node.js 24 LTS; проверяемая локальная версия 24.21.0, npm 11.19.0. Версии прямых зависимостей фиксируются точно, разрешённое дерево — lockfile. TypeScript 5.9.3 выбран совместимым с type-aware tooling; Prisma 7.10.1 — стабильный согласованный набор CLI/client/adapter вместо опубликованного под latest 8.0 RC.
- React/Vite — самостоятельный SPA каркас, без Next.js и серверной подмены стека. TanStack Query и Zod проверяют health DTO; доменные контракты появятся в следующих этапах.
- API на Express 5, same-origin `/api/v1` через Vite dev proxy. Сейчас только liveness/readiness, JSON errors, request ID, ограничения тела и lifecycle. Это не заглушка каталога или записи.
- Локальный PostgreSQL 18.6 в отдельном Compose project `clinic-foundation`, порт только `127.0.0.1:55432`, отдельный volume. Существующие контейнеры других проектов не изменяются. Образ закреплён digest `sha256:10a5c69a83035ab5239f5620d708520e8b28f5aa1f2b20143e6024532edadfb5` в Compose и CI. Обновления образа выполняются осознанно с повторной проверкой.
- В этапе 1 Prisma настраивается без доменных моделей/миграций; проверяется schema/config. Readiness и диагностика используют `pg` как транспорт PostgreSQL. Prisma Client и adapter будут подключены к repositories после появления моделей этапа 2; фиктивную таблицу ради генерации не создавать.
- `.env` существует только локально, игнорируется; `.env.example` не содержит действующих ключей. Setup генерирует случайный пароль только для локальной синтетической БД и не перезаписывает существующее окружение.
- npm install scripts разрешены по точным версиям только для esbuild, Prisma CLI и Prisma engines. Транзитивный `minimatch` закреплён override на 11.0.1 для устранения [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) в lint tooling; это переход через major, поэтому lint/типизация/сборка проверяются после обновления. Пересмотреть override, когда upstream tooling включит исправленную версию штатно; `npm audit fix --force` не используется.
- `DATA_MODE=synthetic` — единственный поддерживаемый режим основы. Персональных данных, auth cookie, форм и боевых контактов здесь нет. Нет внешних fonts/maps/analytics; локальные шрифты поставляются пакетами с лицензиями.

## Запуск и проверки

Нужны Node.js 24.11+ в ветке 24, npm 11 и запущенный Docker с Linux containers. Проверенная локальная версия Node записана в `.node-version`. Команды выполняются из корня проекта:

```sh
npm ci
npm run setup
npm run db:up
npm run db:validate
npm run db:check
npm run dev
```

`setup` создаёт локальный `.env` со случайным паролем синтетической PostgreSQL и сохраняет существующий файл. Если меняется порт/имя БД/пароль, вручную согласовать `POSTGRES_*` и `DATABASE_URL`; файл и его значения не публиковать. При уже созданном volume переменные PostgreSQL не меняют пароль существующего пользователя автоматически.

Web: `http://127.0.0.1:5173`, API: `http://127.0.0.1:3001`. `/api/v1/health/live` проверяет процесс, `/api/v1/health/ready` выполняет SELECT 1. На этапе 1 readiness не заявляет готовность бизнес-функций или юридическую готовность к запуску. Ошибка БД даёт 503 без адреса/пароля; liveness остаётся 200. Контракты проверяются на frontend, ошибки имеют requestId.

`npm run dev` собирает contracts и запускает watch для contracts, API и Vite. После проверки остановить Ctrl+C. `npm run db:down` останавливает только Compose project клиники; volume сохраняется. Сначала `npm run build`, затем `npm run start --workspace @clinic/api` запускает собранный backend. Vite preview — только просмотр frontend, production reverse proxy ещё не настроен.

| Команда                    | Проверка                                                                          |
| -------------------------- | --------------------------------------------------------------------------------- |
| `npm run format:check`     | Формат кода/документов, без изменения референса Stitch                            |
| `npm run lint`             | TypeScript/React и общие правила ESLint                                           |
| `npm run typecheck`        | Strict TypeScript во всех workspace и служебных TS файлах                         |
| `npm test`                 | 15 проверок окружения и HTTP boundary; отдельная ephemeral HTTP-служба            |
| `npm run db:validate`      | Конфигурация Prisma/schema, без миграций и генерации моделей                      |
| `npm run db:check`         | Реальный PostgreSQL, версия, доступность btree_gist; никаких CREATE               |
| `npm run test:integration` | Интеграционный тест PostgreSQL 18, требуется запущенная БД                        |
| `npm run build`            | contracts + API tsc + web tsc/Vite                                                |
| `npm run smoke`            | Build, временные API/Vite, HTTP/proxy/реальный DB readiness; процессы закрываются |
| `npm audit`                | Известные уязвимости разрешённого lockfile на дату запуска                        |

На ограниченной машине тестам нужны права на loopback HTTP/PostgreSQL и создание временных процессов. Проверки не заменяют будущие тесты конкурентного бронирования и RBAC. Health-ответ не содержит версий зависимостей, переменных окружения и данных посетителей.
