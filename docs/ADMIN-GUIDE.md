# Рабочее пространство клиники

Локальный адрес: `http://127.0.0.1:5173/admin` после `npm run dev`. Если ноутбук перезагружен, запустите Docker, `npm run db:up`, затем `npm run dev`. Повторять seed, setup и установку зависимостей при каждом запуске не нужно. Это синтетическая среда, не готовая к приёму реальных данных.

## Доступ

Готового пароля нет. Первый ADMIN создаётся оператором через `npm run staff:bootstrap` в приватном интерактивном терминале согласно [AUTH.md](AUTH.md). После пароля нужен новый код Authenticator. Пароль без MFA не открывает рабочее пространство. Если код уже использован, дождитесь следующего; не повторяйте вход много раз подряд.

Если первый ADMIN уже создан, но его email забыт: оператор после проверки личности запускает `npm run staff:recover-admin`, вводит подтверждение `RECOVER FIRST ADMIN`, новый пароль и MFA key/код. Процедура восстанавливает только первоначальный аккаунт с сохранившейся ролью ADMIN, отзывает сессии и показывает email для входа в приватном терминале. Не пересылайте вывод с адресом или секреты. Повторный bootstrap для восстановления не используется. Для остальных сотрудников — `npm run staff:credentials` с известным email.

Чтобы поменять email, оператор запускает `npm run staff:email`: текущий адрес, новый адрес дважды, подтверждение `CHANGE EMAIL`. Пароль/MFA/роль сохраняются, все сессии отзываются; следующий вход — с новым адресом. Если адрес занят, изменения не применяются. Через веб-панель смена email пока не предусмотрена. Не присылайте адреса/секреты в чат и не сохраняйте transcript терминала.

ADMIN управляет каталогом, назначениями услуг, сотрудниками и аудитом, а также расписанием и записями. RECEPTIONIST работает с расписанием и записями одной клиники. Разделения на персональные кабинеты врачей/филиалы нет; эти роли являются разрешением на соответствующие общеклинические операции. Права проверяются API при каждом запросе.

Смена собственного пароля — «Мой пароль», после неё нужно войти заново. «Выйти» отзывает текущую серверную сессию. При сетевой ошибке выхода экран закрывается, но отзыв на сервере не подтверждён: восстановите связь, войдите и повторите выход либо попросите ADMIN отозвать сессии. Не оставляйте устройство разблокированным.

## Записи

В «Записи на приём» выберите дату в зоне `Asia/Almaty`, врача и статус. Страницы содержат по 20 строк. Поиск номера работает на текущей странице; поиска по телефону и массового экспорта контактов нет. Список содержит номер, время, услугу, врача, статус и цену из snapshot. Имя и телефон доступны только в открытой карточке, её чтение фиксируется в аудите.

`PENDING` уже занимает время, но ожидает подтверждения сотрудника. Свяжитесь с посетителем по утверждённой процедуре клиники и подтвердите заявку. Интерфейс не отправляет SMS/email. Для отмены проверьте номер и подтвердите действие в диалоге. Для переноса выберите услугу, врача, дату и реальный свободный слот. Цена/длительность проверяются сервером повторно. Если время успели занять, исходная запись сохраняется: обновите карточку и выберите другое время. При конфликте версии сначала прочитайте изменения другого сотрудника.

«Завершена» и «Неявка» доступны только в разрешённом состоянии и времени. Терминальные записи не редактируются произвольно. Дополнительное создание доступно по кнопке «Создать запись по коду пациента». Посетитель сам подтверждает согласие на /ru/phone-consent или /kk/phone-consent и сообщает код (5 минут, одно использование). Сотрудник выбирает услугу/врача/слот и вводит код, не заполняя согласие за посетителя. См. PHONE-BOOKING.md: только synthetic, юридическая применимость не проверена; без кода запись не создаётся. Обычная онлайн-запись остаётся основной.

## Расписание

«Календарь врачей» показывает рабочие интервалы и приёмы за день либо семь дней от выбранной даты, с пагинацией. Свободные слоты рассчитываются для выбранных врача, услуги и дня. Это реальные данные API, без drag-and-drop с локальным фиктивным сохранением.

Добавляйте конкретные интервалы. Перерыв — разрыв между ними, выходной — отсутствие интервалов. Не меняйте и не удаляйте интервал, если существующий приём окажется вне работы: сервер отклонит действие. Сначала обработайте соответствующие записи. У интервала нельзя заменить врача; создайте другой интервал. При параллельном редактировании перечитайте актуальное расписание.

## Каталог, сотрудники и аудит

ADMIN редактирует отдельные RU/KK тексты, цену в KZT и длительность в минутах. Slug задаётся при создании. Фото — существующий безопасный локальный ключ, без загрузок/внешних ссылок. Назначения услуг открываются из строки врача. Деактивация услуги, врача или назначения закрывает новые заявки и не отменяет уже созданные приёмы: их нужно разобрать отдельно. Исторические цена и длительность не переписываются. Публичный сайт берёт свежие данные API; SEO HTML-снимки обновляются сборкой согласно [STAGE-5-REPORT.md](STAGE-5-REPORT.md).

Новый сотрудник создаётся неактивным без секретов. Оператор выдаёт пароль/MFA через `npm run staff:credentials` после проверки личности; UI не показывает секреты и не заменяет эту процедуру. Изменение роли/блокировка отзывает сессии. Последнего действующего ADMIN нельзя заблокировать или понизить. Действия с доступом требуют подтверждения.

«Аудит» показывает технические события, идентификаторы и время. Контактов, паролей и MFA в журнале нет. ADMIN может зафиксировать проверенное обращение об отзыве согласия в карточке: сначала проверьте личность по утверждённому регламенту. Операция не удаляет данные, не отменяет запись и не подменяет юридическую процедуру удаления/обработки обращения.

## Ошибки и инциденты

При истечении/отзыве сессии данные карточки убираются, нужен повторный вход. При возвращении в скрытую вкладку сессия проверяется заново. Фоновый `GET /auth/me` не продлевает 30-минутное бездействие. «Недостаточно прав» не обходите другой ссылкой: обратитесь к ADMIN. При ошибке сети обновите данные и проверьте результат до повторного изменения; административные изменения не обещают идемпотентность публичной заявки.

При подозрении на чужой доступ прекратите работу, сообщите ответственному и попросите отозвать сессии. Не отправляйте скриншоты карточек, cookies или секреты в чаты/логи. Юридические сроки, ответственные, восстановление, выдача доступа и работа с реальными данными утверждаются до production на этапе 7.

Интерфейс сотрудников RU/KK: переключатель сверху, выбор сохраняется при переходах (/admin?lang=kk). Поля каталога остаются раздельными RU/KK; даты/статусы/ошибки/подтверждения локализованы. Профессиональная языковая и ручная приёмка персоналом до реальных данных остаются открытыми.
